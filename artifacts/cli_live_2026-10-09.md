## Interpretation (operator analysis, 2026-10-09)

Re-run with `dbt` on `PATH`: the 2026-10-08 infra wipeout is gone, and the
OpenRouter free router accepted 2 of 3 requests — first measured authoring
quality in this project. Notable points:

- The router picked a *different* model per request (`cohere/north-mini-code:free`
  for plain, `dots-studio/dots-3-note-preview:free` for composite) — exactly the
  provider behavior §3.1 warns about, and provenance captured both identities.
- Composite needed 4 attempts (~120k input tokens) before acceptance: the bounded
  repair loop demonstrably works live, with structured feedback converging to a
  verified instance (realized small/157 rows).
- Combined dies on the provider two runs in a row, both times after heavy
  reasoning (64k reasoning tokens here): the hardest prompt + free-tier
  flakiness, not a verdict on feasibility. Pattern, not proof.
- Gemini stays out, with a telling split: `connect` (model metadata) succeeded —
  otherwise the harness would report `unavailable`, not `provider` — so the key
  and model id are valid and only the `generateContent` calls fail. Plain (74s)
  and composite (61s) look timeout-shaped; combined (7.7s) fails fast, i.e. an
  instant provider error, not a refusal (refusals classify separately and none
  was recorded). The sanitized stderr lines from the pytest output
  (`provider failure: gemini request failed ...`) would pin the exact status —
  they contain no key material by design, so they are safe to share.
